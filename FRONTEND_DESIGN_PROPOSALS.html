WatchParty 前端落地实施方案与 UI 设计稿比较

契约基准：UNIVERSAL_ALIGNMENT_SPEC.md v1.0.0-FINAL

根据权威契约规范与产品要求，本次前端改造将彻底移除 mock 数据，严格通过 /api/* 与 /socket.io/* 代理与后端交互，支持权威时钟 5 次 NTP 采样校准、三段式追帧算法、OpenList 自然排序/A-Z过滤/搜索、ASS/SRT 本地字幕隔离。

1. 前端技术栈与核心模块落地矩阵 Next.js 16 + Tailwind 4 + Socket.io-client
功能模块 契约对应接口 / 信令 核心实现机制
时钟同步引擎 (ClockSync) CMD:clockSync ➔ serverTimeMs 进入房间立即连续 5 次 NTP 采样取中位数算出基准偏移 $\Delta t$，每 30s 周期校准；三段式追帧（≤250ms保持, 250~1000ms微调 rate±5%, >1000ms seek）。
房间门禁与 PIN 验证 GET /api/rooms/:id
POST /api/rooms/:id/access		 探查不存在时显示 404，PIN 保护时展示 4 格输入与 5 次 429 限速防御；成功写入 localStorage room_token_<id>。
OpenList 媒体选择器 GET /api/media/list
GET /api/media/search
POST /api/rooms/:id/media/resolve		 限定 Anime/Film/TV Shows 三根目录；支持 A-Z 快速过滤与全局中文搜索；自然排序（第2集排在第10集前）；临时直链解析（403/410单次重试）。
房间控制与乐观并发 CMD:play, CMD:pause, CMD:seek, CMD:playlistAdd, CMD:lock 所有修改携带当前 expectedRevision；遇到 REVISION_CONFLICT 自动拉取最新快照；房主锁严格前端防越权拦截。
本地字幕与 WASM 渲染 GET /api/rooms/:id/media/subtitle 支持 ASS/SSA/SRT/VTT；字幕选择与 ±0.1s 偏移纯本地状态，绝不广播污染全房。

3. 下一步实施计划
  • 步骤 1：用户选定 UI 布局方案（推荐方案 A，或桌面方案 A / 移动端方案 B 自适应）。
  • 步骤 2：完善 web/lib/contracts.ts 严格对齐 RoomSnapshot, MediaSource, PlaylistItem, RoomMember。
  • 步骤 3：重构 web/lib/socket.ts 与权威时钟 5 次 NTP 采样校准及三段式追帧逻辑。
  • 步骤 4：落地真实媒体选择器（OpenList 目录、A-Z过滤、中文搜索、直链解析）。
  • 步骤 5：落地房间主播放器（HTML5/HLS/YouTube 内核、本地 ASS/SRT 字幕渲染）。
  • 步骤 6：执行前端 npm run build 与 npm run lint 验收检查。
