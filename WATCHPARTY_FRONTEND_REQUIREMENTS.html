1. 使用说明与优先级

本文覆盖旧的 FRONTEND_BACKEND_ALIGNMENT.md 中冲突的产品要求。旧文档只能用于了解现状，不能继续作为目标协议实现。

  • 本文决定功能、信息、状态和交互结果，不决定具体布局、组件外观或视觉风格细节。
  • 前端 agent 不得自行扩大媒体范围、重新加入聊天或修改权限语义。
  • 目标后端协议尚需改造，前端必须通过独立的 API/Socket 适配层接入，不允许页面组件直接散落调用。
  • 设计阶段使用真实中文文案和真实状态，不用 lorem ipsum、假延迟、假媒体、假遥测数据填满界面。

2. 产品目标与边界

必须实现

  • 创建和加入临时房间。
  • 可选 4 位数字 PIN。
  • OpenList 目录浏览、中文搜索和批量加入。
  • HTTPS 视频直链、HLS、YouTube。
  • 播放、暂停、进度、倍速、循环和播放列表同步。
  • 房主锁、在线成员和主动转让房主。
  • ASS/SSA/SRT/VTT 外挂字幕。

明确不做

  • 账号、注册、头像上传、好友或历史云同步。
  • 聊天、回复、弹幕、表情反应。
  • Neko、共享浏览器、标签页共享、屏幕共享。
  • WebRTC、Magnet、WebTorrent。
  • 服务端视频代理、转码或媒体文件下载。
  • MKV/WASM 通用播放器、音轨切换。
  • 房间持久化和服务重启恢复。

使用环境

  • 私人 VPS，典型房间 2–5 人。
  • 全站由外层 Caddy Basic Auth 保护。
  • 桌面 Chrome/Edge 是完整体验目标。
  • 移动端保证加入、观看和基础控制。
  • Safari、HEVC、AV1 只做能力检测后的 best-effort。

3. 页面与核心流程

3.1 首页

首页只承担进入服务和恢复本地上下文，不承担媒体播放。

  • 两个主要任务：创建房间、加入房间。二者必须在视觉和语义上清楚区分。
  • 加入支持房间 ID、/room/:id 路径或完整邀请链接。
  • 最近房间只来自本机真实访问记录；没有记录时显示空状态，不注入演示房间。
  • 创建房间必须打开创建弹窗，不允许前端本地生成房号后直接跳转。

3.2 创建房间弹窗

  • 字段：昵称、可选 4 位数字 PIN、可选初始媒体。
  • 初始媒体允许三种入口：暂不选择、从 OpenList 选择、粘贴直链/HLS/YouTube。
  • 提交期间禁用重复提交；由后端创建房间并返回真实房间 ID、访问凭据和房主凭据。
  • 创建成功后进入房间；失败时留在弹窗内显示可恢复错误，不清空用户输入。

3.3 加入与 PIN 门禁

  • 先查询房间摘要。房间不存在时显示明确的不存在页面，不自动创建同名房间。
  • 无 PIN 的房间直接进入；有 PIN 时显示昵称和 PIN 输入。
  • PIN 支持逐格输入、粘贴、退格回跳和 Enter 提交。
  • 区分 PIN 错误、尝试过多、房间消失和网络错误。
  • 鉴权成功后保存房间访问凭据并连接 Socket；不能使用固定演示 PIN 或定时器模拟成功。

3.4 房间主界面

必须同时容纳播放器、当前媒体信息、媒体入口、播放列表、成员/权限和本地字幕控制。具体排布由前端 agent 提案。

  • 播放器是主要视觉对象；辅助区域不能长期遮挡画面。
  • 房间 ID、复制邀请链接、在线人数、房主身份和锁定状态始终可找到。
  • 房主转让、清空/删除播放列表等高影响操作需要确认。
  • 全屏时保留必要播放控制，复杂管理功能退出全屏后操作。

4. 媒体选择器功能要求

媒体选择器是一个功能面板，不规定必须使用抽屉、弹窗或独立页面。前端 agent 应在设计稿中比较不同组织方式。

4.1 OpenList 根目录

  • Film
  • Anime
  • TV Shows

doujin 与 OST 不得显示，也不能通过拼接路径访问。

4.2 浏览和搜索

  • 支持根目录切换、面包屑、返回上层、单层目录列表和刷新。
  • 支持 OpenList 全局中文搜索，并允许将结果限定在某个允许根内。
  • 搜索结果必须显示所在路径，避免同名文件无法区分。
  • 目录和搜索结果至少显示名称、文件类型、大小、兼容性和不兼容原因。
  • 列表使用自然排序，确保第 2 集排在第 10 集之前。

4.3 兼容性

状态前端行为示例
可尝试播放允许加入播放列表；真正加载时再做浏览器能力检测。MP4、WebM、M3U8
环境相关允许尝试，但提示浏览器/编码支持不确定；失败后给出明确原因。HEVC/AV1 封装、特殊音频编码
明确不支持仍显示文件，但禁用播放和加入操作，并提示未来可由 mpv 客户端支持。MKV、非媒体文件

4.4 添加行为

  • 单击受支持视频可以“立即播放”或“加入队列”，两种行为必须可区分。
  • “添加当前文件夹”只扫描当前层级，不递归；只加入受支持视频；自然排序。
  • 播放列表总上限 200 项；达到上限时报告实际加入数量和跳过数量。
  • 字幕文件不能作为视频加入，只能在字幕选择流程中使用。

4.5 粘贴链接

  • 支持 HTTPS 普通视频直链、M3U8 和 YouTube 视频链接。
  • 禁止 javascript:、data:、Magnet 和未知协议。
  • 识别失败时说明支持的来源，不把任意文本当成房间 ID 或媒体地址。

5. 房间成员与权限

操作房间锁定房间解锁
播放、暂停、seek、倍速、循环仅房主所有成员
切换媒体、添加/排序/删除播放列表仅房主所有成员
锁定/解锁房间仅房主仅房主
转让房主仅房主仅房主
音量、静音、字幕、字幕偏移、全屏每位用户本地控制每位用户本地控制
  • 房间创建者通过后端发放的 owner token 成为房主，不以 Socket 加入顺序判定。
  • 房间默认锁定。非房主操作被拒绝时，保持本地播放器与服务端状态一致，并给出短暂明确提示。
  • 成员列表显示昵称、在线状态和唯一房主标识，不显示头像上传入口。
  • 房主转让流程：选择在线成员 → 二次确认 → 等待后端确认 → 更新双方权限。
  • 转让成功后旧房主立即失去权限；新 owner token 仅在目标成员浏览器保存。
  • 不做房主掉线自动接管。新房主刷新或重连后使用其 token 恢复身份。

6. 播放器与同步

播放适配器

  • OpenList：先按稳定 mediaId 解析临时直链，再交给原生视频。
  • 普通直链：原生 <video>。
  • HLS：原生优先，否则使用 hls.js。
  • YouTube：IFrame Player API。

共享状态

  • 当前媒体、播放/暂停。
  • 基准进度、倍速、循环。
  • 锁定状态、房主、播放列表。
  • 服务端版本号 revision。

仅本地状态

  • 音量与静音。
  • 全屏和控制栏显隐。
  • 字幕选择、样式和时间偏移。
  • 临时错误展开状态。

6.1 同步策略

  • 服务端快照是权威状态；不得用某个客户端的假“host timestamp map”作为权威。
  • 偏差不超过 250 ms：不修正。
  • 偏差 250–1000 ms：短时轻微调整播放速度，回正后恢复房间倍速。
  • 偏差超过 1 秒：直接 seek 到服务端目标位置。
  • YouTube 按 IFrame API 能力降级，不承诺与原生视频相同的精度。
  • 界面只显示真实可解释的同步状态，例如“已同步”“正在校准”“落后 1.4 秒”；禁止展示固定的 4.8 ms、6.2 ms 等模拟数值。

6.2 媒体错误恢复

  • OpenList 直链加载失败或疑似过期时，自动重新解析同一 mediaId 一次。
  • 二次失败后停止自动重试，显示失败阶段和可执行动作。
  • 不允许静默改用 WatchParty 后端代理完整视频。
  • 浏览器不支持编码时，保留播放列表项并允许房主跳过，不把它当作网络错误。

7. 字幕要求

  • 支持外部 ASS、SSA、SRT、VTT，以及浏览器/HLS 原生暴露的标准字幕轨。
  • 同目录自动匹配时，只匹配规范化后与视频同主文件名的字幕。
  • 用户可从任意一个允许的 OpenList 根目录手动浏览并选择字幕。
  • 不做跨目录模糊自动匹配，不从任意 MKV 中提取字幕。
  • ASS/SSA 使用 libass/WASM 客户端渲染；SRT 客户端转换；VTT 优先使用原生轨道。
  • 字幕文件上限 5 MiB。超限、编码异常或解析失败时显示明确错误。
  • 字幕选择、开关和时间偏移仅影响当前用户，不写入房间共享状态。

8.1 错误文案规则

  • 说明发生在哪一层：房间、权限、OpenList、直链、浏览器格式或字幕。
  • 提供用户能执行的下一步，例如重试、重新选片、跳过或返回媒体库。
  • 不要使用“协同引擎故障”“未知异常”等装饰性术语掩盖具体问题。
  • Toast 只用于短暂确认；需要用户处理的错误必须留在相关区域。

9. 前端目标接口契约

以下是目标契约。当前后端仍使用旧的 /createRoom 和 CMD:*/REC:* 协议，前端 agent 不应把旧协议继续扩散到页面组件中。

9.1 核心类型

type MediaSource =
  | { kind: "openlist"; mediaId: string; title: string; container: string }
  | { kind: "http"; url: string; title?: string }
  | { kind: "hls"; url: string; title?: string }
  | { kind: "youtube"; videoId: string; title?: string };

type RoomSnapshot = {
  revision: number;
  source: MediaSource | null;
  positionSeconds: number;
  paused: boolean;
  playbackRate: number;
  loop: boolean;
  locked: boolean;
  ownerClientId: string;
  playlist: MediaSource[];
};

9.2 HTTP

接口前端用途
POST /api/rooms提交昵称、可选 PIN、可选初始媒体；接收房间 ID、访问 token、owner token。
GET /api/rooms/:roomId进入前获取存在性、PIN 状态和在线人数。
POST /api/rooms/:roomId/access验证 PIN 并获得访问 token。
GET /api/media/roots获取允许浏览的 OpenList 根。
GET /api/media/list获取单层目录项。
GET /api/media/search执行 OpenList 中文搜索。
POST /api/rooms/:roomId/media/resolve在播放前解析 OpenList 临时直链。
GET /api/media/subtitle获取受大小限制的字幕文本。

统一错误格式为 { code: string, message: string }。页面逻辑根据稳定 code 分支，message 负责展示。

9.3 Socket

  • 握手提供稳定 clientId、房间访问 token 和可选 owner token。
  • 服务端连接后下发完整房间快照和成员列表。
  • 共享修改必须使用 ack；成功后以服务端快照或增量事件为准，不先永久修改本地共享状态。
  • 必须处理过期 revision、无权限、凭据失效、房间消失和重连后重新同步。
  • owner token 轮换事件只能在目标成员连接上接收并持久化。

9.4 前端代码边界

  • lib/api：HTTP 客户端、错误映射和运行时校验。
  • lib/socket：连接、鉴权、重连、事件类型和 ack。
  • lib/player：Native/HLS/YouTube 统一适配接口。
  • lib/subtitles：字幕获取、转换、渲染和本地偏移。
  • 页面组件只消费类型安全的领域接口，不直接拼接 OpenList 路径或临时直链。

10. 前端 agent 的交付流程

  1. 需求复述：先列出本文中的功能边界和发现的现有实现冲突，不写代码。
  2. 静态设计：制作至少三套明显不同的信息架构方案，均覆盖首页、创建弹窗、PIN、房间、媒体选择器、成员转让和关键错误状态。
  3. 等待选择：把三套方案放在同一份可直接对比的 HTML 中，等待用户选择；此时停止，不改真实组件。
  4. 功能实现：选定后先建立类型、API/Socket/播放器适配层，再替换页面中的演示状态。
  5. 响应式和无障碍：补齐移动端基础流程、键盘路径、焦点、对比度和 reduced-motion。
  6. 端到端验证：使用两个浏览器上下文验证真实房间同步和权限。

10.1 固定视觉约束

  • 深色模式，页面主背景为纯黑 #000，主文本为白色。
  • 信息密集，文案简短；不使用装饰性卡片堆叠、巨大圆角和胶囊外框泛滥。
  • 不在每个章节上方添加浅灰色副标题，不使用英文长破折号。
  • 不使用持续脉冲、旋转、模糊或闪光动画；加载状态优先使用静态文字、进度或低成本过渡。
  • 除上述约束外，布局、视觉层级和组件造型由前端 agent 在设计稿中提出。

10.2 必须从现有初稿删除或替换

  • 本地随机生成房间 ID、固定演示 PIN、setTimeout 模拟鉴权。
  • 演示最近房间、演示播放列表、演示音轨和演示字幕。
  • Magnet 输入提示、标签页共享、遥测统计和单数字毫秒偏差。
  • 聊天、弹幕、回复、反应、头像图片。
  • 音轨切换和任何暗示服务支持转码或 MKV 通用播放的入口。

11. 前端完成验收

  • 首页不再用假房号或假历史推动流程。
  • 创建弹窗能提交可选 PIN 和可选初始媒体，并正确处理失败。
  • 有 PIN、无 PIN、不存在和限速四类加入路径均可操作。
  • OpenList 三个根可浏览和搜索，路径越界在界面中不可构造。
  • MKV 可见但不可加入；兼容文件可以立即播放或加入队列。
  • 当前目录批量加入是非递归、自然排序且不超过 200 项。
  • Native、HLS 和 YouTube 播放适配器均通过真实状态驱动 UI。
  • 两个浏览器中的播放、暂停、seek、倍速、循环和播放列表保持同步。
  • 锁定时访客的所有共享修改都被拒绝，解锁后可协作。
  • 房主转让会令旧 token 失效，新房主刷新后仍能恢复身份。
  • ASS/SSA/SRT/VTT 可选择；字幕和偏移不会影响其他成员。
  • 直链过期只自动重新解析一次，不经 WatchParty 服务端传输完整视频。
  • 桌面完成全功能；移动端能加入、观看、播放/暂停和查看当前状态。
  • 界面中不存在聊天、共享浏览器、Magnet、音轨和假遥测残留。
  • 键盘操作、焦点可见性、对比度和 reduced-motion 达标。
WatchParty 前端需求基线。后续视觉稿可以变化，但不得改变本文的产品边界、权限语义和媒体数据流。
