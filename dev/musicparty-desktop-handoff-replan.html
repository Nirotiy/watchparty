目标与固定边界

在 WatchParty 仓库建立共享桌面壳，保留两个品牌与独立账号、服务会话。先完成 MusicParty 核心听歌流程，再将 WatchParty 既有能力接入统一壳。两个产品可同时连接房间，同一时刻只有一个产品拥有音频焦点。

  • 音频和视频统一使用 Rust/libmpv，窗口生命周期与音频焦点由桌面壳管理。
  • 首版 MusicParty 只做邀请兑换，不做完整注册与账号管理；服务端继续拥有播放、队列、同步与冲突裁决权。
  • 支持多个服务、HTTP、HTTPS、自签名证书、用户显式导入 Cookie，以及远程 Docker 承担平台 Cookie 会话的模式。两种 Cookie 用途需通过契约区分。
  • 不做本机 Docker 编排、代理、离线播放、DRM、地区限制绕过、全局快捷键与系统媒体控件。
  • 歌词或封面失败不影响音频；媒体解析或音频失败停止该项并报告，禁止自动降级播放。
  • 凭据只进入 Windows 系统安全存储，不出现在普通 WebView、日志或诊断导出。设置与缓存进入桌面应用数据目录。
  • 不修改线上部署、生产数据库或日常预览渠道。远程验收先明确独立测试对象。

以下为阶段 1 实施前记录，WS 与歌词的最新实现以文末阶段 1 更新及 contracts/desktop/api.html 为准。

范围为 MusicParty 服务端与契约。WatchParty D0–D3 继续由客户端 agent 负责。本次不会改动其组件、依赖或构建产物。三个音乐平台指网易云、YouTube、Bilibili；首版客户端验收目标是 Windows x64，不增加 macOS/Linux 交付。

已支持的源码事实

  • desktop.go 注册 GET health、capabilities，POST invites/redeem，GET search/{platform}，GET media/{platform}/{songId}/resolve、cover、lyrics，均位于 /api/desktop/v1。独立 desktop platforms 路由不存在，需核对客户端是否使用 capabilities.providers 或现有 /api/platforms。
  • websocket.go 当前注册 /ws?room-id={roomId}；不是 /api/desktop/v1/ws?roomId=。首帧 player.state，重连发送快照；未实现 client.hello/server.hello 协商。未知会话在升级后以 1008 关闭。
  • server.go 全局启用 CSRF；邀请兑换明确豁免，其他非安全且未豁免请求匹配 MP_CSRF 与 X-CSRF-Token。CSRF 失败当前只有 403，无 JSON 错误码。之前仅查看 desktop.go 得出的“没有 CSRF”推断不成立。
  • 会话由 Set-Cookie 建立，私有房间还使用 MP_ROOM_ACCESS。客户端必须处理响应 Cookie 和私有房间授权；不能只持久化 MP_SESSION/MP_CSRF。客户端 Cookie 保留能力仍由 WatchParty agent 提供当前执行证据。
  • API 版本 2026-01、最低客户端 0.2.0、服务端常量 1.2.0、生成契约版本 2.0.0 各有不同含义，不能混作同一个版本。

  • 已修正 contracts/desktop/api.html 的 WS 路径与 hello 描述，并补齐搜索、歌词、封面和 CSRF 例外。
