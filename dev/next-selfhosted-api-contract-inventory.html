目标边界

之后的功能改动、缺口补强和验收都以 web/ Next.js 自托管网页为目标。根目录 Vite 客户端已经从源码、根构建、CI、README 和通用 Dockerfile 中移除；/api/media/roots 等桌面兼容能力仍保留。共享逻辑来自 desktop-shell/shared/，修改前需要确认桌面影响范围。

当前工作区有大量既存未提交改动。盘点针对当前检出的代码和可读文件，不覆盖这些改动的运行时效果，也不表示相关部署配置已上线。web/ 本身当前没有已报告的工作区改动。

批准设置与签发路径

批准设置与人类认证由 Next Node Route Handler 承接：web/app/api/catalog-approval/settings/route.ts 和 web/app/api/catalog-approval/libraries/[libraryId]/approval/route.ts。签发处理器把凭证以 X-WatchParty-Approval 转发到后端 POST /api/admin/media-libraries/:id/approval。VPS Compose 将独立配置文件挂载给 Next 容器，客户端默认 secret 模式有明确实现；这不是服务端缺路由。之前把代理入口误当作后端路由，结论已更正。

Socket.IO 房间契约

方向事件用途与归属
连接上行认证字段：roomId、clientId、accessToken、可选 ownerToken、clientProtocol: 2web/lib/socket.ts 建连；服务端 bindRooms.ts 校验并加入房间。
服务端下行REC:snapshot、REC:members、REC:ownerToken、REC:error初始/更新房间状态、成员、owner token 交付和协议错误；网页均有处理器。
客户端命令CMD:name、CMD:clockSync、CMD:play、CMD:pause、CMD:seek、CMD:rate、CMD:loop、CMD:lock、CMD:mediaSet成员名称、时钟对齐和播放状态控制；网页通过 acknowledgement 接收命令结果。
客户端命令CMD:playlistAdd、CMD:playlistRemove、CMD:playlistMove、CMD:playlistPlay、CMD:playlistNext、CMD:playlistAutoNext、CMD:transferOwner共享队列、自动下一项及房主转移；服务端对桌面接收者有专门 owner grant 交付路径。
传输分工网页使用 Socket.IO；当前桌面 Tauri adapter 使用 HTTP native 路由。共享 Room 语义和状态，传输协议不同。没有找到桌面 shell 使用上述 CMD:* Socket 命令的调用。

网页与桌面共用的 HTTP 表面

/api/media/capabilities、/api/media/libraries、/api/media/list、/api/media/search 和主要标题库读取路径同时出现在 Next API wrapper 与桌面 IPC adapter 中。媒体库和标题墙不是桌面独占能力。两端共享后端服务和数据，但 UI、授权头及房间传输不同。目录审批部分桌面侧存在管理员 API 调用/校验，网页也有交互；必须逐端核对对应路径与鉴权，不应从同一服务端能力推断 UI 行为完全一致。

实施顺序

  1. 批准设置和签发由 Next Route Handler 承接，后端只负责管理员签发。新增测试锁住 Next handler 到后端端点的完整转发。
  2. 补充自动化契约测试：至少覆盖 Next 使用的批准设置/签发、房间、媒体解析与 handoff 路径，并验证 Socket 命令和事件名；测试应以当前生产自托管 Next 为基线。
  3. 对 Vite 进行单独下线盘点：找出 build/CI/README/部署和服务端兼容路由依赖，再逐项移除已证明无用的部分。
  4. 后续产品功能与补强只改 web/。当前网页导入了 desktop-shell/shared/catalog-refresh 与 desktop-shell/shared/catalog-exclusions；需要改共享逻辑时应先确认不会把桌面端纳入本轮功能范围。

方法：静态比对 web/lib/api.ts、web/lib/socket.ts、网页调用点、server/app.ts 路由注册、server/core/http/、server/core/socket/bindRooms.ts，并搜索桌面 adapter 与 MCP catalog 调用。没有运行端到端请求，也没有访问线上环境。
