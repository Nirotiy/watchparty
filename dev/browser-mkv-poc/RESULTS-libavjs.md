# libav.js Browser MKV POC Results

Updated: 2026-10-07

## Scope

The POC demux and packet source now use `@libav.js/variant-webcodecs` 6.10.9 and `libavjs-webcodecs-bridge` 0.3.2. The existing page flow and `RangeFile` response checks remain in place. ASS rendering uses JASSUB 2.5.18 on a separate overlay canvas. This work remains isolated under `dev/browser-mkv-poc/` and is not connected to room playback.

The Mediabunny baseline is archived in commit `c068eae2f`.

## Remaining Acceptance Work

1. **Edge 当前树呈递异常**：先建立最小复现并确认是否为 Edge 154 特有；在没有证据前不要把 Chrome 的 v8 呈递结论外推到 Edge。可先保留 Chrome 优先，或为 Edge 增加独立兼容策略。
2. **A/V 物理同步**：Chrome 已在笔记本 HDA 输出完成非静音 5 分钟播放与 330 秒 WASAPI loopback；用户确认短测和 5 分钟听感均无滋滋声。仍未把显示输出与 loopback 音频放到共同时间轴，不能宣称物理 A/V 偏差 <100 ms。下一步测起播、5 分钟、seek 后恢复及 underrun。
3. **基准机 20 分钟门槛**：当前树样本 43 的 20 分钟结果来自 i7-14650HX/32GB/RTX 4060 高配机；未在约定的近 5 年中端、4 核、8GB、集显设备上验证。需要在该级别设备测 1080p30 连播 20 分钟及性能/掉帧；物理同步门槛需采用上项共同时间轴测量。
4. **签名 URL 过期/403 恢复**：代码已有 403 后等待观众粘贴新 URL 并对同一区间重试一次的路径，但目前没有浏览器端强制过期/403 故障注入实测。需要验证 probe/read 两条路径、只重试一次、seek/播放恢复、URL 不进日志或持久存储。
5. **部署发布**：本地 Caddy 修复链已通过；真实 VPS 尚未应用 `Access-Control-Expose-Headers` 配置，也未在实际部署 Origin 重测。需 owner/运维另行安排并明确授权；本 handoff 不要求直接改生产。
6. **WASM 回退边界**：用户确认下载/启动路径仍未实现，因此相关能力/负载测试尚不能跑。MPEG-2 按决定由源文件转码；E-AC-3 和其他原生不支持轨道继续走 MPV 兜底，除非另立实现任务。
7. **许可证与分发材料**：补齐 `THIRD_PARTY/NOTICE`、LGPL-2.1/OFL-1.1 全文、JASSUB 组合依赖 notices、FFmpeg/内嵌库源码获取声明，并由 owner/法务确认后再声称可分发。这是发布阻塞，不是浏览器播放测试。
