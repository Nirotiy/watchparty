Linkle 功能与协议边界

  • 浏览与活动会话分离。浏览别的房间不退出当前会话；只有确认切房才调用既有切换事务，失败必须回滚旧会话。
  • 暂停、下一首和随机分别读取各自房间锁。暂停锁只阻止“正在播放到暂停”，不阻止已暂停后的恢复；管理员没有这三项锁的特殊豁免。
  • seek 尚未统一。浏览器允许实际点歌者、可管理房间者或无 enqueuedById 曲目；Go Runtime 当前只允许管理员或实际点歌者。不能照抄浏览器按钮状态。
  • 桌面适配层的 player.play/player.pause/player.seek 与 Go WebSocket 路由的 control.toggle-pause/control.seek/control.next/control.toggle-shuffle 尚未发现别名映射。当前 App 的 Linkle 暂停实际是 NativeAudioPlayer 本地暂停，不是共享房间控制。
  • 共享控制未接线前，真实 UI 不得把按钮做成可执行。设计稿可展示最终可用、锁定、等待确认和拒绝状态，但工程实现必须禁用真实发送。
  • 完整浏览器对齐范围还包括：队列多选与排序、来源与分页搜索、歌词和翻译、个人喜欢、房间与个人歌单、房间/公共/系统聊天、历史和未读、成员、账号、来源与媒体管理、布局和快捷键。不要只实现三个分页后声称全链路完成。
